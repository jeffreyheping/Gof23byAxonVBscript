# 23 个设计模式精讲 —— VBScript 版

## 关于本书

本书系统讲解 GoF（Gang of Four）在《设计模式：可复用面向对象软件的基础》一书中提出的 23 个经典设计模式，并以 **VBScript** 为主要载体，在 **传统 VBScript** 与 **AxonASP** 两种语法下实现对照，再以 **VB.NET** 作为语法完备的对照基准。每一个模式都给出可运行示例，并标注各运行时下的妥协点与缺失语法项，便于读者直观感受语言特性如何影响模式落地。

## 为什么用 VBScript 讲设计模式

VBScript 是一门诞生于 1996 年的弱类型、基于 COM 的脚本语言，至今仍运行在 Classic ASP、Windows 脚本宿主、嵌入式自动化等大量遗留系统中。它的语法极简——只有 `Class`/`Function`/`Property`/`Dim`，没有继承、没有接口、没有泛型、没有静态变量、没有事件机制——这恰好是一个"反面教材"：用一门特性最少的语言去实现 23 个 GoF 模式，每一种妥协、每一种变通都会被放大到读者眼前。

换句话说，**VBScript 不是用来演示设计模式最优解的语言，而是用来理解设计模式为什么要这么设计的语言**。当你看清了"没有接口时工厂方法为什么别扭"、"没有继承时模板方法为什么变形"、"没有事件时观察者为什么臃肿"，再回头看 Java/C#/Go 的实现，会有完全不同的体会。

## 四种运行时

本书涉及四种运行时，分属三种语法体系。传统 VBScript 代码同时在三种引擎下测试，Axon VBScript 代码在 AxonASP 下运行，VB.NET 代码在 .NET 下运行。

### 1. 传统 VBScript（cscript / WSH）

指 Microsoft 原生的 VBScript 引擎，运行于 Windows Script Host（`cscript.exe`/`wscript.exe`）和 Classic ASP（IIS）。这是 VBScript 的"原貌"——语法极简，只有 `Class`、`Function`、`Property`、`Dim` 等基本构件，所有变量皆为 `Variant` 弱类型。不支持继承、接口、多态、重载、静态变量、事件、泛型等现代 OOP 特性。本书的传统 VBScript 版代码以此引擎为基准编写。

### 2. AxonASP（[github.com/guimaraeslucas/axonasp](https://github.com/guimaraeslucas/axonasp)）

AxonASP 是用 Go 语言从零实现的跨平台 Classic ASP 运行时（Linux / Windows / macOS），内置单遍编译器和栈式字节码 VM。在完全兼容传统 VBScript 语法的基础上，AxonASP 引入了多项现代化扩展：

- **`Implements` 接口**：支持接口定义与实现，让多态派发有了编译期契约约束。
- **`Static` 静态变量**：函数内 `Static` 变量在调用间保持值，支持对象引用。
- **`Event` / `RaiseEvent` / `WithEvents`**：完整的事件机制，观察者模式可原生落地。
- **`For Each` 自定义集合迭代**：通过 `[DispId(-4)]` 转发内置 Collection 枚举器，迭代器模式"完全消失"。
- **强类型（`As Type`）**：字段、参数、返回值均可标注类型，消除整类运行时类型错误。
- **UDT（`Type`）/ `Enum` 枚举 / `IsNot` 运算符**：值语义结构体、命名常量集合、更清晰的空值判断。

这些扩展让大部分 GoF 模式能以更地道的方式落地。本书的 Axon VBScript 版代码以此引擎运行。

### 3. ASPPY（[github.com/PieterCooreman/ASPPY](https://github.com/PieterCooreman/ASPPY)）

ASPPY 是用 Python 实现的 Classic ASP / VBScript 运行时，跨平台运行于 Python 3.8+。它实现了完整的 Classic ASP 对象模型（`Request`/`Response`/`Session`/`Application`/`Server`）和近乎完整的 VBScript 内置函数库。ASPPY 的语法与传统 VBScript **完全一致**，不引入任何扩展——它验证的是同一份传统代码在另一套引擎上的可移植性。ASPPY 将 ASP 页面编译为 Python 字节码并缓存，修改文件后自动重编译。本书的传统 VBScript 版代码同时在 ASPPY 下测试。

### 4. VB.NET（.NET CLR）

VB.NET 是 .NET 平台上的完备 OOP 语言，拥有继承、接口、泛型、委托、事件、`Shared` 静态成员、`Private` 构造函数、`ReadOnly` 字段等全部现代语言特性。本书每一章附一段 VB.NET 实现，作为**语法完备的对照基准**——当你在 VBScript 中不得不做出的每一处妥协，在 VB.NET 中都有"正确答案"可对照。VB.NET 代码在 `Option Strict On` + `Option Explicit On` 下编译运行，杜绝隐式类型转换。

### 运行时与代码版本的关系

| 运行时 | 语法体系 | 运行的代码 |
|--------|---------|-----------|
| 传统 VBScript (cscript) | 传统 VBScript | 传统 VBScript 版 |
| AxonASP | Axon 扩展 VBScript | Axon VBScript 版 |
| ASPPY | 传统 VBScript | 传统 VBScript 版 |
| VB.NET (.NET) | VB.NET | VB.NET 版 |

传统 VBScript 版代码在三套引擎（cscript、AxonASP 传统模式、ASPPY）下测试通过，验证其可移植性；Axon VBScript 版在 AxonASP 下运行；VB.NET 版在 .NET 下运行。

## 本书结构

本书按 GoF 的传统分类组织 23 个模式：

- **创建型模式（第 1–5 章）**：单例、工厂方法、抽象工厂、建造者、原型。关注"对象怎么创建"。
- **结构型模式（第 6–12 章）**：代理、外观、适配器、桥接、组合、装饰器、享元。关注"对象怎么组合"。
- **行为型模式（第 13–23 章）**：策略、观察者、模板方法、迭代器、责任链、命令、状态、中介者、访问者、备忘录、解释器。关注"对象怎么协作"。

每一章遵循统一结构：

1. **核心思想**——一句话点出模式的本质。
2. **示例说明**——用最简单的故事讲清楚模式要解决的问题。
3. **传统 VBScript 版**——可运行的完整代码，附"妥协说明"。
4. **Axon VBScript 版**——可运行的完整代码，附"妥协说明"。
5. **VB.NET 版**——语法完备的对照基准，展示"不需要任何妥协"的实现。
6. 若 AxonASP 仍有未解决的语法点，会显式标注 **缺失语法点**，并对照 Go 语言的等价做法。

附录给出 23 个模式的实现状态总览、缺失语法点优先级，以及本书实际用到的 AxonASP 新特性清单。

## 怎么读

- **初学者**：按章节顺序读，先看"核心思想"和"示例说明"，再对照三版代码读"妥协说明"。
- **有 OOP 基础的读者**：可直接跳到 Axon VBScript 版和 VB.NET 版，重点看"缺失语法点"小节，了解 AxonASP 与 Java/C#/Go 的差距。
- **VBScript 老兵**：重点关注传统版的妥协说明——这些正是你过去 20 年用 VBScript 写代码时遇到的痛点，本书把痛点逐一命名并对照解决。
- **AxonASP 用户**：本书所有 Axon 版代码均已通过 AxonASP 运行时实测，可作为模式实现的参考模板。

## 约定

- 传统 VBScript 版和 Axon VBScript 版的输出统一通过 `Response.Write` 输出；VB.NET 版通过 `Console.WriteLine` 输出。
- 代码中所有 `Response.Write` 输出均为无换行输出，多行展示仅用于阅读方便。
- 注释使用中文，与代码同语言。
- "妥协说明"中的 **缺失语法点** 一律加粗，并与附录中的优先级表对应。
- 涉及 Go 语言对比时，遵循 Go 1.18 之后的语法（含泛型）；若 AxonASP 当前状态等同 Go 1.17 之前，会显式说明。
