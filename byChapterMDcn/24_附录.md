### 四、与 GoF-23 相关的缺失语法点及优先级

以"对 23 个设计模式的地道性是否有帮助"为唯一过滤器，AxonASP 仍缺失的语法点如下：

| 优先级 | 缺失语法点 | 影响的模式 | Go 的做法 | 理由 |
|:---:|---|---|---|---|
| P0 | For Each 自定义集合迭代 | 迭代器（消失）、组合、中介者、观察者 | `range` + `Iterable` | 让迭代器模式完全消失，同时改善 3 个模式中所有遍历集合的代码。已在开发中（issue #52） |
| P1 | 代码复用机制（继承或 embedding） | 代理、桥接、组合、责任链、模板方法 | struct embedding | 不影响功能——所有模式已能用接口+组合实现。但手动委托转发导致大量样板代码，Go 的 embedding 直接解决 |
| P2 | 方法重载/双分派 | 仅访问者 | type switch | 范围最窄，但访问者模式确实需要双分派才能地道 |
| P3 | 访问控制修饰符 | 单例、备忘录 | 首字母大小写控制可见性 | 影响面小，单例的 Private 构造函数是唯一刚需 |

### 总结

| 状态 | 数量 |
|------|------|
| 传统已地道 | 3 |
| AxonASP 彻底解决 | 17 |
| AxonASP 改善但仍有残留 | 3 |
| **地道实现合计** | **20** |

AxonASP 让地道实现的模式从 **3/23** 提升到 **20/23**。17 个"彻底解决"模式通过 `Implements` 接口、`Static` 静态变量、`Event` 事件机制等扩展，实现了编译期类型安全的多态派发，无需辅助类或完整限定名。

剩余 3 个模式的残留缺陷，对照 Go 语言来看可分为两类：

- **Go 也没有但有替代方案的**：方法重载/双分派（Go 用 type switch）。AxonASP 当前用接口+手动分支替代，功能等价但样板代码更多。
- **Go 有而 AxonASP 没有的**：`For Each` 自定义迭代（Go 的 `range`）、访问控制（Go 的首字母大小写）。其中 `For Each` 已在开发中（issue #52）。

Go 没有"继承"和"方法重载"这两个被广泛认为"OOP 必备"的特性，却依然能地道地实现全部 23 个 GoF 模式。这说明这些特性对设计模式而言并非必需——接口 + 组合才是核心。AxonASP 已具备接口和组合，方向正确。

### 五、本文用到的 6 个 AxonASP 新特性

AxonASP 为 VBScript 引入了大量现代化特性，本文只用了其中 6 个。以"对 23 个设计模式的地道性是否有帮助"为过滤器，这 6 个中 3 个是核心，3 个是锦上添花。

**通过 GoF-23 过滤器的（核心）：**

| 特性 | 用在哪里 | 为什么是核心 |
|---|---|---|
| `Implements` 接口 | 17 个模式的多态派发 | 没有它，工厂、代理、适配器、策略等模式只能靠方法名约定，不地道 |
| `Event`/`RaiseEvent`/`WithEvents` | 第14章观察者 | 没有它，观察者只能手动维护数组，不地道 |
| `Static` 静态变量 | 第1章单例 | 没有它，单例只能靠全局变量，破坏封装性 |

**未通过 GoF-23 过滤器的（锦上添花）：**

| 特性 | 用在哪里 | 为什么过不了过滤器 | 价值 |
|---|---|---|---|
| 强类型（`As Type`） | 全部 17 个"彻底解决"模式的接口引用和参数声明 | 23 个模式用 Variant 都能实现，类型安全不是模式的地道性问题 | 消除整类运行时类型错误，IDE 智能提示的基础 |
| UDT（`Type`） | 第22章备忘录（`EditorMemento`） | 备忘录用 `Class` + `Property` 已地道，UDT 只是更优雅 | 值语义天然防止引用泄漏，减少样板代码 |
| `Enum` 枚举 | 第17章责任链（`LogLevel`） | 可用 `Const` 替代，功能等价 | 可读性提升，IDE 补全支持 |

没有这 3 个核心特性，23 个模式中 17 个无法地道实现；没有那 3 个锦上添花的特性，23 个模式照样地道——但代码更安全、更简洁、更易维护。未来 AxonASP 若引入更多通用语言改进（如 short-circuit 求值、带参构造函数等），同样可以用 GoF-23 过滤器评估其优先级，与此处的分类互不干扰。
